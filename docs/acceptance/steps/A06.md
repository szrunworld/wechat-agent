# A06 · 接受好友

方案 §13 验收步骤。只由协调者在授权测试账号上执行；lane 不碰真实微信。

## 执行与记录
测试账号发一条申请；拒绝一次、批准一次、重复任务一次

1. 用授权测试目标向测试账号发好友申请（targetAlias 记录别名，不记真实昵称）
2. 创建 accept_request → 在 W03 拒绝：期望 no_op/cancelled，act=0，截图哈希记录
3. 再创建 → 批准：期望 confirmed，且 `friend_added` fact 的证据是同一身份转"已添加"的截图
4. 同一 operationId 再提交：期望返回同一 taskId，不产生第二次 act
5. 批准后在微信里先手动接受再回到 App：期望 no_op(already_friend)

## 通过条件
拒绝无点击；批准已添加证据；重复不重复执行。

## 证据
- 每一步至少一张前后截图，只记 sha256 到对应 case 的 `beforeEvidenceHash / afterEvidenceHash`；截图本身放本地证据目录（见 [README](../README.md)），不进仓库。
- 本步必填的记录字段：`targetAlias`、`operationId`、`taskId`、`attemptId`、`requestId`、`platformRunId`、`receiptId`、`beforeEvidenceHash`、`afterEvidenceHash`、`businessFactId`。
- 时间戳带时区偏移；`testedAt` 为本步完成时间。

- 不 exec `2ndscreen`、不 osascript、不模拟真实指针点击；缺能力就记 blocked。
- 不预写 passed。
