# A12 · 签收放量

方案 §13 验收步骤。只由协调者在授权测试账号上执行；lane 不碰真实微信。

## 执行与记录
逐 F/T 汇总 passed/failed/blocked/not_run；明确 disabled 功能

1. 跑 `npm test -w tests/integration`：lint 通过，无未执行却写 passed 的记录
2. 按 T01–T42 汇总四种 result，分别统计 Fake 级与真机级证据
3. 列出仍为 disabled 的功能及原因（CR01–CR04）
4. 签收人与复核人分别署名；阻断项进 defectId

## 通过条件
全部必需门禁通过才称完整 P0；阻断项明确列出。

## 证据
- 每一步至少一张前后截图，只记 sha256 到对应 case 的 `beforeEvidenceHash / afterEvidenceHash`；截图本身放本地证据目录（见 [README](../README.md)），不进仓库。
- 本步必填的记录字段：`operator`、`reviewer`、`defectId`。
- 时间戳带时区偏移；`testedAt` 为本步完成时间。

## 关联用例
[T01](../cases/T01.md)、[T42](../cases/T42.md)

## 禁止
- 不对未授权真实联系人发送任何验收消息或申请。
- 不 exec `2ndscreen`、不 osascript、不模拟真实指针点击；缺能力就记 blocked。
- 不预写 passed。
